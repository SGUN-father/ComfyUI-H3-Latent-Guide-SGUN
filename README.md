# H3-Latent-Guide-SGUN

制作：神棍（SGUN）。主节点：`H3 长视频：分段生成 + 合并 by神棍`。

开发交接、代码结构、参考项目和独立审查重点见同目录的 `开发说明.md`。

## 数字人长视频（独立新增节点）

`H3 数字人：原音频驱动长视频 by神棍`（`H3DigitalHuman`）独立于原有长视频节点。连接 MODEL、CLIP、视频/音频 VAE、参考图、口播或歌曲，以及 `H3 长视频提示词`，按音频长度自动完成循环。完整视频和分段视频均由外部官方 Save Video 正式保存、显示预览；本节点仅使用临时片段缓存，不保存 LATENT，不提供断点恢复或逐段抽卡。

无需合并开关：完整视频接 Save Video 才实际合并、保存整片；分段视频接另一个 Save Video 才逐段正式保存。两路可单独连接，也可同时连接；没有通往保存/预览等终端的下游时，本节点不执行。完整 VIDEO 是延迟合并对象，补接另一种保存方式可复用已有生成缓存。

- 每段时长自动取最近的 5.875、8、10.125、12.25 或 14.375 秒，包含续接上下文；默认 8 秒。显存不足时先降低每段时长或百万像素；模型权重本身仍需相应显存/内存。
- 固定 24fps，39 帧视频上下文对应整数音频 token。续段按原曲绝对位置读取含重叠区的音频，冻结整条音频潜变量和视频上下文；不继承模型生成的声音。共同时间网格避免循环累积音频偏移。
- 音频整体在 CPU 重采样一次用于驱动。每段只解码当前画面，临时缓存带对应原音的 MP4；下一段只保留独立 CPU 视频尾部。最终合并以完整原始音频重新合成一次，不串接分段 AAC 音轨。原音长度不变，视频末尾最多多不足一帧；指定时长按选定音频及目标帧数计算，避免重采样取整额外增加一帧。
- 默认分块解码，以文件流输出合并 VIDEO，不把整片画面加载到内存。内部只在 ComfyUI temp 下缓存当前任务片段，不向 output 写入视频、任务目录、进度清单或备份。整轮生成完成后，下游 Save Video 才开始正式保存；中断或失败清理本次临时缓存，不支持断点恢复。
- 参考图使用官方同款可扩展接口，接入后自动增加下一接口，最多 9 张。按接入顺序在提示词中引用 `<Picture 1>`、`<Picture 2>`…；接口后缀从 0 开始，提示词编号从 1 开始，各段共用素材。
- `prompts` 接现有 `H3 长视频提示词`：共用描述加入每段，分段剧情用独占一行的 `---` 分隔。每块对应一次**实际采样段**，续段包含开头 39 帧（1.625 秒）上下文，不等于新增画面时长，也不是精确歌曲分镜时间表。段数始终按音频自动决定；不足且未开启 `repeat_last` 时，在采样前报错。配套样例开启复用最后一段，以适配任意音频长度。
- 接入 `prompts` 时优先使用分段计划；未接入时兼容原有 `prompt` 字符串，整片复用。旧字符串控件保留在高级选项。可设置音频起点/时长（0 为剩余全部），或接入现有 SIGMAS。锁定音频不会自动新增 `<Audio 1>` 参考标签。

| 设置 / 输出 | 行为 |
| --- | --- |
| 输出 0 / 1 | 保留原顺序：“完整视频” VIDEO、“生成信息” STRING。 |
| 输出 2 | “分段视频” VIDEO 列表，连接另一个 Save Video 自动逐段保存，供后续剪辑。 |

逐段核对视频帧数、PTS 和音频长度，以保证原生拼接时间轴；这些检查不代替人物、口型和接缝审片。输出对象仍依赖临时缓存，正式保存完成前不要清理 ComfyUI temp。

配套工作流：[数字人自动循环](examples/H3_数字人_自动循环.json)。自带独立 `H3 长视频提示词`，完整视频与分段视频分别连接两个 Save Video；保留标准节点原名。需近期原生 H3 音视频遮罩和支持 `complete_audio` 的官方视频合成接口；本机验证环境为 ComfyUI 0.40.0。

临时输出版通过 27 项数字人 CPU 测试和 3 项真实媒体检查/修正测试；覆盖外接官方 Save Video 保存整片及各段原音、零起点连续时间轴、无正式输出副作用、取消清理和内存释放。此次未重新运行 H3 模型生成。

## 原有长视频节点

一个节点完成 MiniMax H3 Ref2VA 分段采样、原生音视频 LATENT 续接、解码和逐段保存。每段完成后立即保存到 ComfyUI output，中止或报错保留已完成的片段。模型、CLIP、视频/音频 VAE、加速、图片和提示词编辑留在外面。合并视频可选接外部官方 Save Video；不接也正常生成并保存各段。

## 示例工作流

- [数字人自动循环](examples/H3_数字人_自动循环.json)：原音驱动、自动循环、分段提示词和两路外部保存，内置 6 块 Markdown 说明。
- [长视频自定义 Sigmas 版](examples/H3_长视频_一体节点_自定义Sigmas.json)：30 秒相亲故事，3 段 × 10 秒，含人物、场景参考和完整分段提示词、外部采样序列及 9 块 Markdown 说明；需要手动续接时可自行添加 LATENT 读取节点。按 24fps 网格实际导出 243+238+238=719 帧，约 29.96 秒。

长视频示例保留作者当前配置：**0.2 MP、3 段 × 10 秒、DMAD 4step LoRA、5 步 SIGMAS、各段种子 fixed、预览开启且 10fps**；旁边的 10 步 SIGMAS 为未连接备用。新建节点的默认值不变，实际采样步数由当前连接的 SIGMAS 决定。分段保存前缀为 `H3`，可选合并前缀为 `H3_combined`。

下载 JSON 后拖入 ComfyUI，或使用「工作流 → 打开」导入。两份示例的 Markdown 使用说明均已同步：长视频由主节点逐段保存，数字人仍使用外部保存。

相亲示例参考图：[林知夏四视图](examples/assets/blind_date_30s/lin_zhixia_four_views.png)、[陈屿四视图](examples/assets/blind_date_30s/chen_yu_four_views.png)、[咖啡馆场景](examples/assets/blind_date_30s/cafe.png)。将 `examples/assets/blind_date_30s/` 中的三张 PNG 复制到 `ComfyUI/input/H3_examples/blind_date_30s/`，保留文件名，再导入工作流；图片引用顺序为女主、男主、场景。人物四视图只定义同一个人物的外观，剧情中各出现一人。

旧版参考素材仍保留：[红发少年](examples/red_superboy_on_city_roof.png)、[机械巨兽](examples/mecha_dragon_lightning.png)。已有工作流可继续使用；相亲示例也可替换素材并修改对应提示词。

模板保存的是作者本机的模型文件名；导入后按自己的安装情况重新选择 H3 模型、CLIP、视频/音频 VAE 和加速 LoRA。注意力后端与稀疏注意力节点来自新版 ComfyUI；若当前环境不支持所选加速后端，将 MODEL 从 LoRA 节点直接连接到 H3 长视频节点即可。合并视频按外部保存连线使用，无需开关；保存每段 LATENT 默认关闭，需要时在主节点开启。

## 安装与连接

将本目录放入 ComfyUI `custom_nodes`，重启后导入新版配套工作流。不要同时安装旧名和新名两个副本。包来源标识为 `H3-Latent-Guide-SGUN`。使用官方 H3 Ref2VA 权重及其 CLIP、两个 VAE。

使用运行 ComfyUI 的 Python，在 ComfyUI 根目录安装依赖：

```text
python -m pip install -r custom_nodes/ComfyUI-H3-Latent-Guide-SGUN/requirements.txt
```

系统回收站功能使用 Send2Trash；Windows 还需 pywin32 以启用现代回收站后端。缺少依赖时仅无法“一键清理”，不影响生成。

**最低要求：2026-09-21 之后的 ComfyUI（稳定版 v0.38.0 及以上）**，因为依赖官方 H3、V3 API、原生视频接口、`comfy.audio` 音频重采样及自带 PyAV/safetensors。版本过旧时插件加载会直接报错，并列出缺少的官方功能和加入日期，更新 ComfyUI 后重启即可。采样预览出现任何错误只会关闭预览，不影响生成。本次 CPU 验证环境为 ComfyUI 0.41.0、前端 1.55.17。代码不包含 Windows 专属路径或命令，Linux 尚未实机验证。外部加速节点仍有各自环境要求。

必接 `model`、`clip`、视频 `vae`、`audio_vae`、`prompts`。提示词使用配套 `H3 长视频提示词`：固定描述加入每一段，各段剧情用独占一行的 `---` 分隔。`start_segment` 从1开始；提示词不足默认在采样前报错，`repeat_last=true` 可复用最后一段。

- `segments` 是本次新生成总段数，1→1段、2→2段，默认4。上一段 LATENT 不计数，也不加入本次导出。
- 尺寸和时长沿用官方：24fps、17k+5帧网格、尺寸对齐32。5.0/0.4/16:9 对应864×480；四段为124+119+119+119帧，约20.04秒。首段完整保留，续段自动裁掉重叠和同步音频。音轨按导出帧数截齐，H3 音频 token 取整造成的尾部不足会补零。
- `seed_mode` 使用官方 fixed/increment/decrement/randomize。首段使用面板种子；后续按模式变化，递增/递减在范围边界停止。`control_after_generate` 默认 `randomize`（随机），控制下一次任务的起始种子。多段 `randomize` 每次排队重新随机后续段，即使面板首段种子固定；固定/递增/递减及单段模式仍可复用缓存。段数或种子模式通过连线提供且无法提前判定时，会保守重新执行。
- 采样器 `sampler_name` 默认 `er_sde`。
- `sigmas` 可接 Manual Sigmas，接入后直接用于所有片段，覆盖内部 steps/scheduler/denoise；采样器仍生效。未连接则使用面板调度。
- `ref_images`、`ref_videos`、`ref_video_audios`、`ref_audios` 使用官方可扩展接口，各段共用素材。参考视频接24fps IMAGE批次（至少5帧）；视频音轨按相同编号配对。标签编号沿用官方 `<Picture j>`、`<Video j>`、`<Audio j>`。
- 模型和加速在外部调节；内部使用 BasicGuider，无负向 CFG。

## 视频输出、LATENT 保存与合并

**生成完一段就正式保存一段。** 正常生成时，主节点在 ComfyUI output 下创建独立编号批次目录，每段解码、裁掉重复上下文和同步音频后，立即写入 `segment_NNNN.mp4`。完整写入后才确认保存成功；中止或报错不会删除已完成的视频、重抽记录或 LATENT。不再提供“分段视频”输出接口，也不需要外接分段 Save Video。

| 参数 | 默认 | 行为 |
| --- | --- | --- |
| 保存前缀 `filename_prefix` | H3 | 默认在 output 下创建一层编号目录；根目录只放正式分段 MP4，辅助文件集中在 `_data`。正常生成使用独立批次；重抽 output 中的片段时沿用原批次，忽略当前前缀。 |
| 保存每段 LATENT `save_latents` | false | 开启后，在批次的 `_data` 中额外逐段保存完整原生联合音视频 `.h3latent` 和清单 `segments.jsonl`。关闭不影响分段视频及重抽记录保存。 |

**“合并视频”接外部官方 Save Video，才保存整片。** 返回的 VIDEO 是惰性组合，下游保存时才实际合并；不接、断开或屏蔽合并保存节点，主节点仍可运行并逐段保存，不会因此报错，也不会额外产生合并文件。主节点为输出节点，无须依赖 Save Video 触发。合并文件名与编码设置仍由外部 Save Video 控制。

默认正式目录示例（正常新任务依次使用 `H3_00002` 等目录，重抽留在原批次）：

```text
output/H3_00001/
    segment_0001.mp4
    segment_0002.mp4
    segment_0002_retry_001.mp4
    segment_0002_retry_002.mp4
    _data/
        segment_0001.h3segment.json
        segment_0002.h3segment.json
        segment_0002_retry_001.h3segment.json
        segment_0002_retry_002.h3segment.json
        ...同名上下文与对应编号的接缝预览文件
```

开启 LATENT 保存后，`_data` 中还会包含 `segment_0001.h3latent`、`segment_0002.h3latent` 和 `segments.jsonl`。清单每行记录一个已保存 LATENT 的实际种子、尺寸、帧数和续接方式；关闭时不创建清单，但分段 MP4 与轻量重抽记录仍保存。

正式分段使用官方默认 H.264/AAC，当前默认 CRF 为18；可选外部合并 Save Video 的 auto/MP4、codec auto 可按官方规则流式拼接视频包及音轨，其他编码/CRF可能触发转码。下一段只保留必要的 CPU LATENT 尾部，不累积原始 IMAGE；成功与取消任务都会留下已完成分段，需按批次整理磁盘。

四个输出依次为合并 VIDEO、最后一段完整音视频 LATENT、生成信息 JSON、LATENT 文件路径列表。输出 0/1/2 保持原位置；移除原输出 3“分段视频”，原输出 4 的 LATENT 路径列表移至 3。旧工作流导入时移除旧分段出口及其连线，并调整 LATENT 路径槽位；由此失去视频输入的旧分段 Save Video 会自动屏蔽，原有参数值保持对应。新版配套示例已直接移除这个多余的保存节点。

生成信息包含实际尺寸/时长/帧数、实际种子、开关、逐段续接方式和 CPU 尾部缓存字节数；`video_storage=output`，`video_paths` 为带 `[output]` 标记的正式分段路径。`output_subfolder` 始终给出本批次根目录；LATENT 文件路径、下载条目的子目录和 `manifest` 指向 `_data`，其中 `manifest` 仅在 LATENT 保存开启时有值。主节点保留固定高度面板与接缝预览；需要整片播放器时连接外部 Save Video。

## LATENT 续接与重抽

主节点使用固定高度的标签面板，包含“生成设置 / 片段重抽 / 接缝预览 / 生成信息”。参数与提示词在面板内编辑和滚动，切换标签不会撑高节点；生成信息显示实际种子、尺寸、时长与保存路径。旧工作流参数保留，分段出口与 LATENT 路径连线按上述规则迁移。

节点名称、参数和面板跟随 ComfyUI 的界面语言：中文界面显示中文，英文界面显示英文。可在 ComfyUI 设置中切换语言；不会翻译用户的提示词、文件路径或自定义标题。面板内的布尔开关统一使用“开 / 关”（On / Off）下拉框，工作流仍保存原有布尔值。

“预览采样（增加耗时）”默认关闭：不加载预览模型、不额外解码，原生低清采样缩略图也不再追加到节点下方。开启后使用本地 `models/vae_approx/taeh3_temporal.safetensors`，通过 ComfyUI 原生时序 TAEHV 解码器生成连续画面，在原有黑色面板内覆盖循环播放，无音频，不增加节点高度，不依赖 KJNodes，也不调用完整 H3 VAE 做中间预览。预览是近似结果，不代表成片画质。

预览时间轴自动对齐每段实际导出帧数，续段排除重复上下文，不再显示帧数控件；每次更新最多编码 60 张均匀抽取的画面，其余时间轴位置复用最近一张，避免长片段单次推送数 MB。时序解码器直接生成相应的连续帧，不再重复二维预览帧来补齐时长。预览帧率位于开关下方，默认 10fps（1–60）；24fps 与正式视频同速，调低慢放、调高快放，只改预览速度，正式视频仍为 24fps。

权重使用 [TAEHV 作者仓库的 H3 时序版本](https://github.com/madebyollin/taehv/tree/011dfc2112197741c540e0bdd5b7b67bcc930771)，下载其中的 `safetensors/taeh3.safetensors`，另存为上述 `taeh3_temporal.safetensors`；不能使用旧的二维 `taeh3.safetensors`。文件为 22,709,752 字节，SHA256：`4fd022bfcab08772fe0536b17ea1a3bbb5625be11e397868d1c5d891863d4c13`。节点只读取本地文件，不会自动联网下载。

“高级设置与 LATENT 保存”内依次集中显示预览开关、预览帧率、预览更新间隔、预览最长边。更新间隔默认每 2 步一次，最长边默认 768（128–2048），JPEG 质量80。更新更频繁或片段更长会增加预览开销；最长边只限制预览图，不改变正式输出尺寸。点击“返回参数”只隐藏本次覆盖层，已排队任务仍按原开关继续解码；下次排队可重新显示，任务结束后自动恢复参数。预览按任务及工作流归属过滤，避免旧任务或其他工作流的画面覆盖当前节点。需要取消开销时，应在排队前关闭开关。预览模型缺失或解码失败时仅停用该次预览，视频生成继续；用户中止仍正常生效。

在“片段重抽”中选中片段，点击“恢复参数重抽”，会回填生成参数、最终提示词和完整实际种子，并自动使用该段原来的续接上下文；生成段数改为1。“重抽种子方式”默认“随机种子”，每次运行重新随机并记录实际种子；选“原种子”才复用该片段记录的实际种子；选“自定义种子”才显示并使用相邻的“自定义重抽种子”，必须填写 0–18446744073709551615 的完整整数，留空或非法值报错。可修改“重抽提示词”，留空沿用记录；“退出重抽”恢复进入前的参数。模型、CLIP、VAE和参考素材沿用当前连线；通过连线控制的标量需先转回控件才能一键回填。重抽只输出新段，后续内容需沿新结果继续。

对 output 中的片段记录重抽时，新视频保存在原视频所属批次根目录，忽略当前“保存前缀”，不覆盖原版。第 2 段依次生成 `segment_0002_retry_001.mp4`、`segment_0002_retry_002.mp4`；选中某个重抽版本再次重抽，仍沿用第 2 段并继续递增次数。对应记录、上下文、预览和可选 LATENT 以同一逻辑段号及重抽次数保存在 `_data`；清单也在 `_data`。

接缝播放器展示前段末1秒和新段首2秒，保留对应音频，标明交接位置。像素变化检测提示疑似跳变、亮度或颜色台阶，覆盖新段开头2秒；大动作和换光可能触发，提示不代替审片，也不会自动修改画面。预览失败不阻断已完成的视频生成。没有前段视频的外接LATENT会明确显示“未检查”。

“片段重抽”页的“一键清理”只在点击时执行：把当前列表中位于 output/temp 的重抽记录、上下文、短预览等辅助数据移到系统回收站，**原片段和重抽片段的正式 MP4 以及保存的 .h3latent 保留在原文件夹**。点击后先弹出确认框，显示涉及的记录数和批次数；点“刷新已保存片段”后列表包含 output 中所有批次。空的 `_data` 目录可以回收。input 导入记录、参考素材、外部合并视频、其他文件和仍被其他记录使用的共享数据保留。运行或排队期间不能清理。

清理完成后清空已清理的列表项和预览，退出相应重抽；有进入重抽前的快照时恢复参数。正式视频仍可播放，但清理后的记录需从回收站还原才能继续重抽。部分失败时保留失败记录，不会改为永久删除。

每段正式视频保存在 output 批次根目录；轻量 `.h3segment.json` 记录、最小 CPU `.h3context`、`seam_*.mp4` 和 `context_preview_*.mp4` 集中在该批次的 `_data`，可通过“刷新已保存片段”重新载入，不受 ComfyUI temp 清理影响。开启“保存每段 LATENT”才在 `_data` 额外保存完整 LATENT。旧批次的平铺记录仍可读取，不自动移动已有文件。自定义 SIGMAS 重抽使用记录的原始序列；内部调度按恢复后的当前设置计算。此前版本没有完整片段记录，仍可使用下述手动续接方式。

`previous_latent`（上一段 LATENT）替换原 `previous_video`。接上一生成节点的“最后一段 latent”，或配套 `H3 读取音视频 LATENT by神棍`。必须包含完整 H3 视频和音频流，且与新段分辨率一致。直接复制原生尾部上下文，不经过视频压缩或 VAE 往返。

自动恢复某段重抽可使用保存的片段记录和最小上下文，无须额外开启完整 LATENT 保存。若要手动读取任意前段继续生成，需提前开启“保存每段 LATENT”：重抽第3段时，读取第2段 `.h3latent` → 上一段 LATENT；提示词 `start_segment=3`；生成段数=1；保持分辨率，调整种子。比较相同噪声时手动使用原第3段实际种子。输入段不出现在新输出中；后续动作需以重抽的新段继续生成。

读取节点直接在“已保存的 LATENT”下拉列表里选择文件，无需复制路径。自动扫描 ComfyUI `output`、`input`、`temp` 及子目录中的 `.h3latent`，按修改时间排序，最新文件在最前面。生成新片段后点击列表下方的刷新按钮；刷新会选择最新文件，重抽其他段时再选择对应段号。未保存 LATENT 时，列表会提示先开启主节点的“保存每段 LATENT”。

高级选项中的“手动路径（可留空）”保留旧工作流兼容：通常留空；已有路径或路径连线优先于下拉选择。路径仍使用原生 `[output]`/`[input]`/`[temp]` 标记，不带标记默认 input，限定在这些目录内。

`.h3latent` 是 safetensors 格式，分别保存视频/音频张量，保留 dtype、数值及音频取整偏移；使用本插件读取。普通 Save/Load Latent 不支持这类联合 NestedTensor。文件内容变化会更新读取节点缓存指纹。

不接上一段 LATENT 且生成段数=1，可正常生成完整首段。未提前保存 LATENT 时，不能从 MP4 恢复原采样数值；可在同一图直接传最后一段 LATENT，或重新生成需要的段。升级后导入新版一体工作流，旧 VIDEO 接口需改接 LATENT。

## 防偏色与亮度漂移

高级选项 `drift_correction`（防偏色与亮度漂移）默认开启；旧工作流未提供本项时按开启处理，显式保存的关闭值保留。关闭时不计算统计或修改LATENT。开启后，首段保持原样，以其视频LATENT主体的24通道均值和标准差作为本次生成的固定参考；接入上一段LATENT时改以该完整输入片段为参考，跨任务重新测量，不保留全片参考张量。

只在续段采样完成后、解码与LATENT保存前轻量校正视频主体。音频、头部重叠上下文和尾部续接上下文逐值保留；校正在主体两端渐入渐出。固定混合强度0.35，通道增益限制在0.8～1.25，偏移限制在本通道标准差的±0.5内；常量通道或没有足够主体的短片段保持原样。只保留48个float32参考统计值，每次仅将一个通道转换为float32计算，不额外采样、不修改MODEL或SIGMAS，可与动态掩码一起使用。

该功能尝试缓解同场景连续镜头的颜色、亮度和对比度漂移，不能恢复细节，也不保证真实画质收益。主动换光、昼夜变化或换场景时建议关闭，以免正常变化被拉向参考统计。生成信息记录开关值；开启时保存及返回的LATENT与解码使用同一份校正结果。头尾上下文有意保留原始值，严重漂移时仍可能在保留区内可见，需实测检查。

## 动态掩码

`dynamic_mask`（动态掩码）默认true；旧工作流未提供本项时按开启处理，显式保存的关闭值保留。只有接入上一段LATENT或内部续段才生效；全新首段保持普通生成流程。关闭时仍使用原来的H3 keyframe引导。

开启后，把上一段尾部复制到本段将被裁掉的前缀，在采样中按实际sigma调整视频软掩码：远离接缝的上下文允许更多重绘，紧邻接缝的位置保持锁定；新生成区域正常采样，音频上下文保持锁定。采样掩码与H3内部token掩码使用同一套官方映射，避免两者不一致。内部调度和外接SIGMAS均不改写；不增加第二遍采样，不修改保存的上一段LATENT或输入MODEL。

这种机制用于尝试缓解续接漂移、接缝及上下文锁定带来的问题，不能恢复已经丢失的细节，也不能保证越续越清晰。参考项目作者的测试也报告过运动更稳定、清晰度稍降的取舍，参见 [Easy Media实现与作者说明](https://github.com/yolain/ComfyUI-Easy-Media/blob/main/modules/motion_context/drift_control_av.py)。本节点采用独立实现，未证明同样的画质收益；建议用相同模型、参考图、提示词和实际种子分别生成开/关两组，比较后半段。

需要ComfyUI具备原生H3音视频软掩码和ModelPatcher钩子支持；相关官方支持见 [ComfyUI PR #15375](https://github.com/Comfy-Org/ComfyUI/pull/15375)。版本缺少接口或MODEL已经装有其他动态掩码时，会在采样前明确报错，可更新或关闭本开关。加速模型通过克隆保留原有配置，具体加速器仍需实测。每段有少量工作掩码开销，采样完成或异常时释放活动掩码，不跨段累积。

生成信息记录开关值和逐段`continuation_methods`；JSONL清单逐段记录`continuation_method`。`none`为无前段首段，`guide`为普通续接，`dynamic_mask`为本次动态掩码续接。

## 资源与平台

下一段开始前只保留独立复制的CPU音视频尾部，不累积完整中间 LATENT、原始画面或压缩视频缓冲。默认22帧上下文保留39帧完整AV网格；音频引导末端对齐接缝且起点不早于新段起点；最后一段完整 LATENT 作为输出保留。磁盘路径记录仍随段数增长，系统文件缓存也可能增长。

关闭合并省去整片保存、编码/转码处理和整片文件；两种模式均使用磁盘片段。保存 LATENT 需要本段CPU数据写入和额外磁盘空间，不输出整片张量列表。显存主要仍由模型、单段采样和解码决定；外部节点若解码整片为 IMAGE，仍可能占用大量内存。

先运行1–4段，并发1，观察显存、系统内存和可用磁盘再增加段数。资源不足先降低百万像素、每段时长和参考规模。开关不是无限生成或低配置安全保证，没有验证各类设备的统一安全段数。

H3 解码调用官方 VAE Decode，内部原生分块当前使用空间256像素、最低空间重叠64像素、时间切片基准17帧；通用分块参数不控制H3后端，已移除这些控件。参见 [官方配置](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/Ref2VA/video_vae/config.json) 与 [ComfyUI 实现](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy/ldm/minimax/vae.py)。固定图片和描述有助一致性，原生 LATENT 传递不能保证无限长链不劣化。

RunningHub/Linux 尚未实机测试。节点使用原生 ComfyUI，不依赖自定义网页或服务；平台需安装本插件和所需官方版本。云端生成目录不等于跨任务存储，需平台支持保存/下载/上传 `.h3latent`；任务失败时是否保留、展示已保存文件也由平台决定。

## 保留的独立引导与循环工具

`MiniMax H3 潜空间续接引导` 接下一段 positive、空联合 LATENT、上一段完整采样 LATENT、context_frames，输出 positive 和 trim_frames。下一段仍采样新的空 LATENT；正常解码后删掉前 trim_frames 帧和 trim_frames/24 秒音频再拼接。两段须同分辨率、batch=1。对齐后的上下文必须小于本段总帧数，否则提前报错，避免裁剪后没有新画面。

`H3 循环分段提示词` 保留旧循环用法：首段在循环外，Start Loop的initial_iteration_value接首段 LATENT，current_iteration_value接引导previous_latent，续段采样结果接End Loop的next_iteration_value。旧工具的循环次数仍按续接次数计算，不改变新主节点的总段数语义。
